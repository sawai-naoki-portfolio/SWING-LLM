# テスト仕様・結果 — SWING-LLM

## 1. 方針

| 種類 | ねらい |
|---|---|
| ロジックの単体テスト | モデルの部品（MLA・MoE・KV キャッシュ・RoPE・投機的デコード）、生成（JSON 制約・Best-of-N）、データ整備、検証器、評価指標を、小さな入力で決定的に確かめる |
| 安全・セキュリティのテスト | サンドボックスの抜け道、Host / Origin / トークン検証、レート制限、声のクローンの同意、透かし、画像の安全フィルタを、**攻撃側の入力**で確かめる |
| 学習の堅牢性のテスト | 保存の中断・壊れたチェックポイント・データの変更・コーパス作成の中断と再開など、**長時間の学習で起きる失敗**を再現して確かめる |
| 評価ゲート | `run.bat` の評価ステージ（正答率・Function Calling・RAG recall@2・パープレキシティ・PSNR・SNR）でパイプラインの合否を決める（[設計書 7 章](design.md#評価ゲート)） |
| E2E | `run.bat` の verify / check ステージで Web UI を起動し、パイプライン全体を確かめる（手元の Windows で実行） |

ユニットテストは標準の `unittest` で書き、GPU が無い環境でも CPU で通るようにしています。学習済みの重み・外部サービス・大きなモデルの取得が必要なテストは、条件を満たさないときにスキップします。

## 2. 実行方法

```bash
cd prototype
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt

python -m ruff check .                              # 静的解析
python -m mypy                                      # 型チェック（段階導入中の 7 ファイル）
SWI_MODE=TEST python -m tests.run_unit_tests        # すべてのユニットテスト（tests/unit/test_*.py）
SWI_MODE=TEST python -m tests.run_voice_unit_tests  # 音声だけ（test_voice_*.py）
SWI_MODE=TEST python -m swi_llm.eval.rag_eval --min-recall 0.8   # RAG の検索品質
```

プッシュごとに GitHub Actions（`.github/workflows/ci.yml`）でも静的解析と LLM・音声・画像のユニットテストを実行します。

### スキップしたもの

| テスト | 理由 |
|---|---|
| 画像生成・音声合成の E2E（各 1 件） | 学習済みのチェックポイントが必要（リポジトリには重みを含めていない） |
| VAE の知覚的損失（3 件・クラス単位） | ImageNet 学習済みの重みのダウンロードが必要（作業環境から取得できなかった。GitHub Actions では実行される） |
| faster-whisper の実 ASR（1 件） | `SWI_ASR_INTEGRATION_TESTS=1` のときだけ実行 |
| Wikipedia API（1 件） | `SWI_WIKI_INTEGRATION_TESTS=1` のときだけ実行 |

### 代表的なテストケース（抜粋）

| No | ケース | 期待結果 |
|---|---|---|
| 1 | サンドボックスで `().__class__.__bases__[0].__subclasses__()` を実行させる | AST 検査で拒否される |
| 2 | `operator.attrgetter` を使った抜け道のコード | 拒否される |
| 3 | `execute_python` の許可が無い状態で、モデルが `<tool_call>` で呼ぶ | ツールが登録されておらず実行されない |
| 4 | `0.0.0.0` で待ち受け、許可ホストを設定しない | 起動を拒否する |
| 5 | WebSocket に誤ったトークンで接続 | accept の前に close 1008 |
| 6 | 宣言より大きい本文を送る | 本文を読み捨ててから 413（上限つき） |
| 7 | 同意を登録していない話者 ID で声のクローン | `CloningConsentError`。参照音声の復号は行わない |
| 8 | 公開データセットの同意しかない話者でクローン | 拒否（データセット単位の同意はクローンに使えない） |
| 9 | 保存の途中で失敗させる | `.tmp` が消え、直前のチェックポイントは無傷 |
| 10 | 存在するが壊れているチェックポイントから再開 | `CheckpointLoadError` で停止（ゼロから学習し直さない） |
| 11 | コーパス作成を途中で止めて再実行 | 止めずに作った場合とバイト単位で同じファイルになる |
| 12 | 数式の答え `1/2` と `0.5`、`m c^2` と `m*c**2` | 検証器が等価と判定する |
| 13 | MTP の投機的デコードを有効 / 無効にして貪欲生成 | 同じ出力になる |
| 14 | KV キャッシュの容量を超えて書き込む | `ValueError`（黙って壊れない） |
| 15 | 画像の安全フィルタでハッシュ照合がエラーになる | その画像を通さない（fail-closed） |

## 4. 静的解析

| ツール | 対象 | 結果 |
|---|---|---|
| ruff | `prototype/` 全体（構文エラー・未定義名・再定義など、実バグにつながる規則） | All checks passed |
| mypy | 段階導入中の 7 ファイル（トークン予算コーパス・パープレキシティ・VAD・ASR・音質フィルタ・pHash・画像の安全フィルタ） | Success: no issues found |

静的解析を入れたときに、到達しないログ出力の未定義名（5 件）と import の重複（3 件）を見つけて直しました。

## 5. 評価ゲートの結果

| 評価 | 結果 | 備考 |
|---|---|---|
| RAG recall@2 | **8 / 8（100%）**・ゲート 0.8 | 2026-10-25 に作業環境で実行（faiss あり・埋め込みとリランカなし = BM25 主体） |
| その他（パープレキシティ・能力ベンチ・Function Calling・画像・音声） | [設計書 7 章](design.md#評価ゲート)の記録上の実測値 | GPU と学習データが必要なため、公開版の作成時には再実行していない |

## 6. 今後の改善

| 項目 | 内容 |
|---|---|
| 品質のゲートを上げる | 大規模な事前学習のあと、能力ベンチ・Function Calling・パープレキシティのしきい値を「クラッシュ検知」から「品質の基準」に引き上げる |
| 型チェックを広げる | mypy の対象を、触ったファイルから順に増やす |
| E2E を CI へ | 小さなチェックポイントを作って、Web UI の E2E を GitHub Actions でも回す |
